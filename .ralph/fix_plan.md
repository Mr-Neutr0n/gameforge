- [x] TASK-013: Game template presets in `backend/app/templates/presets/`. Each should be ~80-120 lines of working Phaser code with comments marking where the agent should modify. These MUST be working, playable games.

- [x] TASK-015: Error capture bridge. In the base template (task 012), add `window.onerror` and `console.error` interceptors that postMessage to parent. ## Phase 4: Google ADK Agent System
- [x] TASK-016: ADK project setup in `backend/app/agents/`. Create `__init__.py` that exports `root_agent`. Create `config.py` with Gemini model config (gemini-2.5-flash), API key from env. Create `tools.py` with all tool function stubs. Create `runner.py` with the ADK Runner setup, InMemorySessionService, and a function `run_game_generation(prompt, game_id, template_type) -> AsyncGenerator[Event]` that yields events for streaming.
- [x] TASK-017: Implement agent tools in `backend/app/agents/tools.py`: `write_game_code(filename: str, content: str, tool_context: ToolContext) -> dict` — writes/overwrites game code in the session state, `read_game_code(filename: str, tool_context: ToolContext) -> dict` — reads current code from state, `list_game_files(tool_context: ToolContext) -> dict` — lists all files, `get_game_plan(tool_context: ToolContext) -> dict` — returns the current plan from state, `validate_phaser_config(code: str) -> dict` — basic regex checks that Phaser.Game config exists, scenes are defined, preload/create/update methods present, `report_progress(message: str, tool_context: ToolContext) -> dict` — stores a progress message for streaming to frontend.
- [x] TASK-018: Planner agent in `backend/app/agents/planner.py`. An `LlmAgent` with name="planner", model=gemini-2.5-flash. System instruction: "You are a game design planner. Given a game description, output a structured plan with: game_title, game_type (platformer/topdown/shooter/puzzle/custom), scenes (list with name and description), mechanics (player controls, enemies, scoring, win/lose conditions), assets_needed (sprites with descriptions). Output as JSON. Be specific about game mechanics — what happens when player presses each key, how enemies behave, how scoring works." Tools: `get_game_plan`. Output saved to state via `output_key="game_plan"`.
- [x] TASK-019: Code Generator agent in `backend/app/agents/generator.py`. An `LlmAgent` with name="code_generator", model=gemini-2.5-flash. System instruction: "You are a Phaser 3 expert code generator. Given a game plan (in state as 'game_plan'), generate complete Phaser.js code. Rules: (1) Always use Phaser 3 API — new Phaser.Game(), Phaser.Scene, this.physics.add, etc. (2) Generate ONE complete JavaScript file. (3) Include all scenes defined in the plan. (4) Use arcade physics. (5) Draw sprites using Phaser graphics (rectangles, circles) — no external image assets. (6) Handle window resize. (7) Include score display using Phaser text. (8) Add proper create(), update(), preload() lifecycle methods. (9) Code must be immediately runnable — no imports, no modules, pure browser JS." Tools: `write_game_code`, `read_game_code`, `validate_phaser_config`.
- [x] TASK-020: Validator agent in `backend/app/agents/validator.py`. An `LlmAgent` with name="validator", model=gemini-2.5-flash. System instruction: "You are a Phaser.js code reviewer. Read the generated code and check for: (1) Phaser.Game config exists with valid width/height/scene. (2) At least one scene class with create() and update(). (3) Player entity exists with controls. (4) No syntax errors (look for unclosed brackets, missing semicolons). (5) No undefined variables. (6) Physics bodies are added to physics groups correctly. (7) Score or game state tracking exists. Return a JSON with: valid (bool), errors (list of strings), warnings (list of strings)." Tools: `read_game_code`, `validate_phaser_config`. Output saved to state via `output_key="validation_result"`.
- [x] TASK-021: Fixer agent in `backend/app/agents/fixer.py`. An `LlmAgent` with name="fixer", model=gemini-2.5-flash. System instruction: "You are a Phaser.js code fixer. The validation found errors in the game code. Read the current code and the validation errors from state. Fix ALL errors while preserving the game's intended behavior. Write the complete fixed code. Do not add new features — only fix what's broken." Tools: `read_game_code`, `write_game_code`, `validate_phaser_config`. Reads `validation_result` from state.
- [x] TASK-022: Coordinator agent in `backend/app/agents/coordinator.py`. Uses `SequentialAgent` wrapping: planner → generator → validator. If validator reports errors, use a `LoopAgent` wrapping fixer → validator with `max_iterations=3`. The coordinator is the `root_agent` exported from `__init__.py`. Add `before_agent_callback` and `after_agent_callback` on each sub-agent to emit progress events. The full pipeline: plan → generate → validate → (fix → validate) loop → done.
- [x] TASK-023: SSE streaming endpoint in `backend/app/routes/generate.py`: `POST /api/games/{id}/generate` — accepts `{prompt, template_type}`. Creates ADK runner, starts the coordinator agent. Yields SSE events as the agent works: `{"type": "thinking", "agent": "planner", "content": "..."}`, `{"type": "code", "filename": "game.js", "content": "..."}`, `{"type": "validation", "valid": true/false, "errors": [...]}`, `{"type": "fix", "iteration": 1}`, `{"type": "complete", "game_code": "..."}`. Saves final game_code to DB. Saves all steps to conversations table.

## Phase 7: Audit Pipeline
- [x] TASK-032: Logic audit in `backend/app/audits/logic_audit.py`. Automated checks on generated game_code (string analysis, regex, AST-lite): (1) `new Phaser.Game` exists, (2) At least one `Phaser.Scene` subclass or scene config, (3) `create()` method exists, (4) `update()` method exists, (5) Player entity created in create(), (6) Input handling exists (keyboard/pointer), (7) No infinite loops (no `while(true)` without break), (8) Score or state variable exists. Returns `{passed: bool, score: int 0-100, details: [...]}`. Endpoint: `POST /api/games/{id}/audit/logic`.
- [x] TASK-033: UI audit in `backend/app/audits/ui_audit.py`. Checks: (1) Phaser.Game config has valid width/height (> 0, < 4096), (2) Canvas background color is set (not default black), (3) Text objects use reasonable font sizes (12-72), (4) Game area fits within common viewport sizes, (5) No overlapping UI elements in default positions. Returns same format as logic audit. Endpoint: `POST /api/games/{id}/audit/ui`.
- [ ] TASK-034: Code quality audit in `backend/app/audits/code_audit.py`. Checks: (1) No `eval()` or `Function()` constructor, (2) No `var` declarations (use `let`/`const`), (3) All Phaser scenes have `destroy()` or cleanup logic, (4) No `document.` calls outside Phaser API, (5) No `window.location` or navigation calls, (6) No external fetch/XHR calls, (7) Proper use of `this.` in scene methods. Returns same format. Endpoint: `POST /api/games/{id}/audit/code`.
- [ ] TASK-035: Audit orchestrator. After generation completes, automatically run all 3 audits. Store results in `audit_results` table. On game workspace page, show audit results as a quality panel: green/yellow/red indicators per audit category, expandable details. Overall quality score (average of all audits). On game share page, show quality badge if score > 80.
